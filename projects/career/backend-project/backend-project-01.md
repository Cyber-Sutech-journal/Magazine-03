# Backend Project 01 — Task Management API

## سطح پروژه

Beginner

## هدف پروژه

در این پروژه باید یک **Backend API برای مدیریت وظایف شخصی** طراحی و پیاده‌سازی کنید.

کاربر باید بتواند در سیستم حساب کاربری ایجاد کند، وارد حساب خود شود و وظایف خودش را مدیریت کند.

هدف پروژه آشنایی عملی با مفاهیم پایه Backend مانند:

* ساخت API
* کار با Database
* ثبت‌نام و ورود کاربران
* ایجاد، دریافت، ویرایش و حذف اطلاعات
* اعتبارسنجی اطلاعات
* ارتباط بین جداول Database

---

# سناریوی پروژه

فرض کنید می‌خواهیم یک برنامه ساده برای مدیریت کارهای روزانه بسازیم.

هر شخص یک حساب کاربری دارد و بعد از ورود می‌تواند Taskهای خودش را ایجاد و مدیریت کند.

برای مثال:

**Amir** می‌تواند Taskهای زیر را داشته باشد:

```text
- Complete GitHub project
- Study Python
- Read a book
```

اما اگر **Sara** وارد حساب خودش شود، نباید Taskهای Amir را ببیند.

هر کاربر فقط به اطلاعات خودش دسترسی دارد.

---

# بخش اول: کاربران

سیستم باید امکان ثبت‌نام و ورود کاربران را داشته باشد.

هر کاربر حداقل اطلاعات زیر را داشته باشد:

```text
Name
Email
Password
```

مثلاً:

```text
Name: Amir
Email: amir@example.com
Password: ********
```

### نکته امنیتی

رمز عبور کاربران نباید به صورت متن ساده در Database ذخیره شود.

باید قبل از ذخیره‌سازی، رمز عبور را با یک روش مناسب **Hash** کنید.

---

# بخش دوم: Taskها

هر کاربر می‌تواند چند Task داشته باشد.

هر Task حداقل شامل اطلاعات زیر باشد:

```text
Title
Description
Status
Created At
Updated At
```

مثلاً:

```text
Title: Learn FastAPI

Description: Complete the FastAPI tutorial

Status: In Progress

Created At: 2026-09-13
```

وضعیت Task می‌تواند یکی از موارد زیر باشد:

```text
Todo
In Progress
Done
```

---

# بخش سوم: ارتباط User و Task

هر Task باید متعلق به یک User باشد.

یعنی بین User و Task یک رابطه وجود دارد:

```text
User
  |
  |--- Task
  |--- Task
  |--- Task
```

مثلاً:

```text
Amir
 ├── Learn FastAPI
 ├── Complete GitHub Project
 └── Study SQL

Sara
 ├── Learn Java
 └── Complete Assignment
```

بنابراین در Database باید بتوانید مشخص کنید که هر Task متعلق به کدام User است.

### نکته

نحوه طراحی جدول‌ها و ارتباط آن‌ها با یکدیگر بر عهده شماست.

---

# بخش چهارم: عملیات مربوط به Task

کاربر باید بتواند:

### ایجاد Task

یک Task جدید ایجاد کند.

مثلاً:

```text
Title: Learn SQL
Description: Study SQL joins
Status: Todo
```

### مشاهده Taskها

کاربر بتواند تمام Taskهای خودش را مشاهده کند.

همچنین بتواند اطلاعات یک Task مشخص را مشاهده کند.

### ویرایش Task

کاربر بتواند اطلاعات Task خودش را تغییر دهد.

برای مثال:

```text
Todo
↓
In Progress
↓
Done
```

### حذف Task

کاربر بتواند Task خودش را حذف کند.

---

# بخش پنجم: ورود کاربران

کاربر باید بتواند با ایمیل و رمز عبور خود وارد حسابش شود.

پس از ورود، سیستم باید بتواند تشخیص دهد که درخواست مربوط به کدام کاربر است.

از روش مناسب برای Authentication استفاده کنید.

استفاده از **JWT** پیشنهاد می‌شود، اما انتخاب روش پیاده‌سازی بر عهده شماست.

---

# بخش ششم: دسترسی به اطلاعات

کاربر فقط باید بتواند Taskهای خودش را مشاهده و مدیریت کند.

برای مثال:

```text
Amir → Task A
Sara → Task B
```

Amir نباید بتواند Task B را مشاهده، ویرایش یا حذف کند.

---

# بخش هفتم: جستجو و فیلتر

API باید امکان فیلتر کردن Taskها بر اساس وضعیت را داشته باشد.

برای مثال:

```text
GET /tasks?status=done
```

باید فقط Taskهایی که وضعیت آن‌ها `Done` است نمایش داده شوند.

امکان جستجو بر اساس عنوان Task نیز به عنوان قابلیت اضافی پیشنهاد می‌شود.

---

# بخش هشتم: اعتبارسنجی

اطلاعاتی که کاربر وارد می‌کند باید بررسی شوند.

برای مثال:

* ایمیل باید معتبر باشد.
* ایمیل نباید تکراری باشد.
* رمز عبور نباید خالی باشد.
* عنوان Task نباید خالی باشد.
* وضعیت Task باید یکی از وضعیت‌های تعریف‌شده باشد.

اگر اطلاعات اشتباه باشند، برنامه باید پیام خطای مناسب به کاربر برگرداند.

---

# Database

اطلاعات پروژه باید در یک Database ذخیره شوند.

حداقل دو نوع اطلاعات اصلی در Database وجود خواهد داشت:

```text
Users
Tasks
```

به عنوان نمونه، اطلاعات می‌تواند به شکل زیر باشد:

### Users

| id | name | email                                       | password        |
| -- | ---- | ------------------------------------------- | --------------- |
| 1  | Amir | [amir@example.com](mailto:amir@example.com) | hashed password |
| 2  | Sara | [sara@example.com](mailto:sara@example.com) | hashed password |

### Tasks

| id | user_id | title         | description       | status      |
| -- | ------- | ------------- | ----------------- | ----------- |
| 1  | 1       | Learn FastAPI | Complete tutorial | Done        |
| 2  | 1       | Study SQL     | Learn joins       | In Progress |
| 3  | 2       | Learn Java    | Complete course   | Todo        |

در این مثال، مقدار `user_id` مشخص می‌کند که هر Task متعلق به کدام User است.

**طراحی نهایی Database بر عهده شماست.**

# Frontend

ساخت Frontend برای این پروژه **اجباری نیست**.

تمرکز این پروژه روی Backend است.

برای تست API می‌توانید از ابزارهایی مانند:

* Swagger / OpenAPI
* Postman
* Insomnia

استفاده کنید.

بنابراین لازم نیست برای این پروژه یک وب‌سایت کامل طراحی کنید.

اگر به Frontend علاقه دارید، ساخت یک رابط کاربری ساده برای پروژه می‌تواند یک قابلیت اضافی باشد.
